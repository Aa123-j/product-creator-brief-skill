# 产品输入档案

本文件是资料整理方法，不是某条产品线的知识库。每次任务以使用者提供的产品资料为依据；缺少资料时先完成可支持的部分，不推测产品功能。

## 需要提炼的信息

| 字段 | 整理要求 | 用途 |
|---|---|---|
| 产品身份 | 名称、型号、版本及必要的区别 | 避免串用不同产品的卖点 |
| 使用者与情境 | 本次目标人群、动机和适用场景 | 决定内容方向，不以标签代替需求 |
| 主卖点 | 用户提供的事实及其证据位置 | 选择一个可讲清、可展示的主信息 |
| 使用说明 | 操作、限制及对应型号 | 设计真实可拍的演示 |
| 证据 | 来源、日期、指标、条件和范围 | 约束数量、比较与结果表述 |
| 品牌要求 | 明确的必拍元素、语言、平台、CTA | 建立覆盖表 |
| 活动信息 | 已确认优惠、排期、访问入口 | 与稳定产品事实分开 |
| 缺口与冲突 | 尚未确认的功能、体验和资料差异 | 标记待确认或改用可支持表达 |

## 从事实到镜头

每个卖点依次记录：产品事实 → 使用者关心的理由 → 可拍动作 → 能证明什么 → 不能据此证明什么。选择演示方法前确认操作说明，不能为了视觉效果增加没有依据的功能。

多个产品分开整理；产品相似不代表功能、规格或说明相同。资料中的历史脚本是参考方案，不自动成为达人真实经历或当前活动条款。

任务记录可保存在项目的 `creative-context/product-content/`，不随公开技能发布。
